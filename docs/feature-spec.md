# StreakFit 機能仕様書

Duolingo の継続メカニクスを応用した筋トレ習慣化アプリの機能仕様。
根拠となる調査は [Duolingo リサーチ](./duolingo-research.md) を参照。

---

## 0. プロダクト概要

### コンセプト
> 「今日、動画を1本再生する」だけでいい。でも、その1本を途切れさせたくなくなる。

自分で YouTube から見つけたトレーニング動画をアプリに保存し、毎日再生して鍛える。
Duolingo 同様、**アクションの摩擦を極限まで下げつつ**、ストリークと損失回避で継続を強制力に変える。

### コア・ユーザー体験(1日のループ)
1. 通知が届く →(トリガー)
2. アプリを開くと今日やる動画が既にセットされている →(低摩擦)
3. 動画を再生し、終わったら「完了」 →(アクション)
4. ストリーク +1、XP 獲得、ご褒美演出 →(変動報酬)
5. 継続日数・記録が積み上がる →(投資)

### 設計原則
- **摩擦最小化**:アプリを開いたら「今日やること」が即決まっている。選ばせない。
- **1日1コミット**:最小単位は「動画1本の再生完了」。ハードルを上げない。
- **失う恐怖 > 得る喜び**:ストリークを常に主役に置く。
- **休んでも終わりじゃない**:フリーズで完璧主義の離脱を防ぐ。
- **アイデンティティ醸成**:「自分は毎日鍛える人」という自己像を育てる。

## 1. スコープ:MVP と将来機能

段階的にリリースする。**まず MVP で「コアループ + ストリーク + 通知」を成立させる**ことが最優先。
社会機能(リーグ等)は習慣化の土台ができた後。

### MVP(v1)— 必須
| # | 機能 | 目的 |
|---|---|---|
| M1 | YouTube 動画の保存(リンク登録) | コンテンツを貯める |
| M2 | 動画の再生 & 「今日完了」記録 | コアアクション |
| M3 | ストリーク(連続日数) | 損失回避の核 |
| M4 | ホーム画面(今日の1本 + ストリーク表示) | 摩擦最小化の起点 |
| M5 | リマインダー通知 | トリガー |
| M6 | ストリークフリーズ | 離脱防止の安全網 |

### v2 — 定着強化
| # | 機能 |
|---|---|
| V1 | XP・レベル |
| V2 | 週間目標 / デイリークエスト |
| V3 | プレイリスト(部位別・目的別) |
| V4 | 実績バッジ / マイルストーン演出 |
| V5 | 統計・カレンダーヒートマップ |

### v3 — 社会・マネタイズ
| # | 機能 |
|---|---|
| S1 | フレンド & フレンドストリーク |
| S2 | 週次リーグ / リーダーボード |

> (Duolingo データ:共有ストリークがある人は日次完了率 **+22%**、友達を追加した人は完走率 **5.6倍**)。
> フレンド機能(S1)が入り次第、優先実装する。

## 2. MVP 機能詳細

### M1. YouTube 動画の保存

**重要な技術・規約前提:**
YouTube の利用規約上、動画ファイルをダウンロード・再配布することはできない。
本アプリは **「動画そのもの」ではなく「動画への参照(URL / videoId)」を保存**し、
再生は **YouTube 公式の埋め込みプレーヤー(IFrame Player API / 各プラットフォームの公式プレーヤー)** で行う。
これにより規約を遵守しつつ、ユーザー体験としては「自分の動画ライブラリ」を実現する。

**フロー:**
1. ユーザーが YouTube アプリ / ブラウザから「共有」→ StreakFit を選択(OS の共有シート連携)
   - または、アプリ内でURLを貼り付け
2. URL から `videoId` を抽出
3. YouTube Data API(または oEmbed)でメタデータ取得:タイトル・サムネイル・チャンネル名・再生時間
4. ライブラリに保存。任意でタグ付け(部位:胸/背中/脚/腹筋…、種類:HIIT/ストレッチ…)

**データ:**
- `videoId`, `title`, `thumbnailUrl`, `channelName`, `durationSec`, `tags[]`, `addedAt`

### M2. 動画の再生 & 完了記録

- ホームの「今日の1本」から即再生(公式埋め込みプレーヤー)
- 再生完了 or 手動「完了」ボタンで、その日の達成を記録
  - 不正防止より継続促進を優先 → 「完了」は緩めに(自己申告可)。厳密な視聴検知は将来検討
- 完了時に **報酬演出**(XP 加算・ストリーク +1・アニメーション・効果音)

**データ:**
- `WorkoutLog { date, videoId, completedAt, xpEarned }`

### M3. ストリーク(最重要)

- **連続達成日数**をカウント。ホームで最も大きく・目立つ位置に常時表示
- 判定は「その日1本でも完了したか」。ユーザーのタイムゾーンで日付境界を判定
- **マイルストーン**(3・7・14・30・50・100・365 日)で特別演出。7 日目付近を特に重視
- **途切れそうな時の演出**:夜になって未達なら「ストリークが危ない!」を通知・バナー表示
- ストリークが切れた時は、責めずに「再開しよう」と背中を押すコピー

**データ:**
- `Streak { current, longest, lastCompletedDate, freezeCount }`

### M4. ホーム画面

摩擦最小化の心臓部。開いた瞬間に「今日やること」が決まっている。

**レイアウト(上から):**
1. **ストリーク数(特大)** + 炎アイコン
2. **今日の1本**(サムネイル大 + 再生ボタン)— タップで即再生
3. 今日の状態(未達 / 達成済み)
4. XP / レベル進捗バー(v2〜)
5. 下部ナビ:ホーム / ライブラリ / 統計 / 設定

**「今日の1本」の決め方:**
- MVP:ライブラリからローテーション(登録順 or ランダム)/ ユーザーが前夜にセット可能
- 将来:曜日別プレイリスト、部位ローテーション

### M5. リマインダー通知

- **時刻設定**:ユーザーが希望時間を設定(デフォルト提案 + 行動学習で最適化)
- **段階的リマインド**:
  1. 設定時刻に「今日のトレーニングの時間です💪」
  2. 未達なら夜に「ストリーク◯日が途切れそう!あと1本」
- **文面 A/B テスト**の土台を用意(ポジティブ系 vs 損失回避系)
- **パーソナライズ**:名前・ストリーク日数を差し込む
- キャラクター(マスコット)を用意し「愛される催促」に(将来)

### M6. ストリークフリーズ

- ストリークを守る保険。1日達成できなくてもストリークが途切れない
- MVP:初期付与(例:2個)+ 一定日数達成でチャージ / 将来は課金・広告で補充
- **自動適用**:未達で日付が変わる瞬間にフリーズを自動消費(ユーザーの操作不要)
- 使用時に通知:「フリーズでストリークを守りました。明日また続けよう」
- 筋トレは休養日が健康上も必要 → 「計画的休養日(Rest Day)」設定でフリーズ消費なしに休める仕組みも検討

## 3.5. ソーシャル機能:つつく(Nudge)【v3・要注目】

友達がワンタップするだけで、受け取る側には**「友達が誘ってくれた」ような温かい通知**が届く仕組み。
送る側のコストはほぼゼロなのに、受け取る側には強い社会的トリガーが働く——Duolingo の最も
費用対効果の高いリテンション施策のひとつ。

### なぜ効くのか(心理原則)
- **社会的アカウンタビリティ**:「見てくれている人がいる」感覚が実行率を上げる
- **互恵性(レシプロシティ)**:つつかれたら、つつき返したくなる → 相互ループが回る
- **パーソナルな通知**:機械的リマインダーより、人からの誘いの方が圧倒的に開かれる
- **データ**:共有ストリークがある人は日次完了率 **+22%**、友達追加で完走率 **5.6倍**(Duolingo)

### 挙動(コア体験)
1. 友達がまだ今日のトレーニング未達だと、フレンド一覧/フィードで **「つつく」ボタン**が表示される
2. **ワンタップ**で送信(それ以上の操作は不要)
3. 受け取った側に**人からの誘いに見えるプッシュ通知**が届く
   - 例:「💪 ○○さんがあなたをつついています!今日のトレ、一緒にやろう」
   - 例:「🔥 ○○さんが応援しています。ストリークを守ろう!」
4. 通知タップ → そのまま「今日の1本」へ遷移(摩擦ゼロで復帰)
5. 達成後、**「つつき返す/お礼する」**導線を出して相互ループを作る

### バリエーション(プリセット・ワンタップ)
| 種類 | 用途 | 通知トーン |
|---|---|---|
| つつく(Nudge) | 未達の友達を誘う | 明るい催促 |
| 応援(Cheer) | 頑張っている友達を励ます | ポジティブ |
| 称賛(Congrats) | マイルストーン達成を祝う | お祝い |

### 設計上の注意(倫理・UX)
- **罪悪感で追い込まない**:文面は「誘い・応援」トーン。「サボってる」等の非難系は使わない
  (Duolingo の通知は guilt-inducing と批判された経緯があるため、あえてポジティブに寄せる)
- **スパム防止**:同一相手へのつつきは **1日1回まで**・クールダウンを設定
- **受信側のコントロール**:つつき通知のミュート/オプトアウト、相手ごとのブロックを用意
- **フェイク感を出さない**:あくまで「友達が実際にワンタップした」事実に基づく通知にする
  (実在しない友達からの偽通知は信頼を損なうので不可)
- **プライバシー**:達成/未達の状態を友達に見せる範囲をユーザーが設定できるように

### データモデル追加
```
Friendship { id, userId, friendUserId, status, createdAt }
Nudge { id, fromUserId, toUserId, type(nudge|cheer|congrats), sentAt, seenAt, respondedAt }
// レート制限用に (fromUserId, toUserId, date) で送信回数を管理
```

## 4. 画面一覧(MVP)

| 画面 | 内容 |
|---|---|
| オンボーディング | 目的設定 → 最初の動画を1本登録 → 通知許可 → **初日ストリーク獲得**まで最短で到達させる |
| ホーム | ストリーク + 今日の1本 + 完了ボタン |
| 動画プレーヤー | 公式埋め込み再生 + 完了 |
| ライブラリ | 保存動画一覧・追加・タグ・並べ替え |
| 動画追加 | URL 貼り付け / 共有シート受け取り |
| 統計(簡易) | カレンダー・連続記録・累計本数 |
| 設定 | 通知時刻・タイムゾーン・フリーズ・アカウント |

**オンボーディング設計が最重要**:Duolingo が示す通り初期ストリーク形成が離脱を左右するため、
**登録直後にその場で1本再生させ、Day 1 ストリークを獲得させる**ところまでを最短動線にする。

## 6. 未決事項 / 次に決めること

- **技術スタック**:iOS/Android 両対応なら React Native or Flutter が有力。Web(PWA)先行も選択肢。
  → YouTube 公式プレーヤー、プッシュ通知、共有シート連携の実現方法に直結
- **YouTube メタデータ取得**:YouTube Data API のキー運用・レート制限、oEmbed のみで足りるか
- **「完了」判定の厳密さ**:自己申告 vs 視聴時間検知(継続促進を優先し MVP は緩め推奨)
- **休養日の扱い**:フリーズと別に「計画的 Rest Day」を設けるか
- **マネタイズ方針**:サブスク / 広告 / 買い切りフリーズ
- **アカウント**:MVP はローカル保存のみで開始 → 後でクラウド同期、の段階導入も可
